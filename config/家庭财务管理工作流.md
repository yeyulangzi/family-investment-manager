# 家庭财务管理工作流

> 领域边界：
> - 本文件负责家庭财务与投资执行系统的判断顺序、分类词典、流程档位、硬性否决规则和归档口径。
> - 财务团队内部角色清单与文件路径统一以 `references/Agent索引.md` 为准。
> - 如需接入宿主环境（Claude Code/Codex/Copilot）的 Agent 注册与路由，可参考宿主自带的 agent 注册机制。

## 1. 定位

这套系统不是单纯的投资分析工具，而是家庭财务管理和交易纪律系统。

它要回答的不是“这个标的会不会涨”，而是：

1. 家庭资产负债表是否安全。
2. 未来 6-12 个月现金流是否安全。
3. 保险、房产、负债和创业备用金是否构成硬约束。
4. 金融资产配置是否服务于家庭目标。
5. 单次交易是否破坏风险桶、现金安全垫和行为纪律。
6. 每次建议是否有证据、方法、边界、失效条件和复盘机制。

股票、基金、黄金、债券、现金、房产和保险都放在这个系统里。公司股票投资只是长期投资资金下面的一个子模块。

## 2. 方法论底座

本系统使用三层方法论。

### 2.1 家庭财务底层原则

- 资产负债表优先于收益率。
- 现金流安全优先于投资机会。
- 风险保障优先于高波动资产。
- 资产配置优先于单个标的。
- 分散化必须同时看资产类别和风险因子。
- 再平衡是纪律，不是对短期涨跌的情绪反应。

参考底层原则：

- SEC / Investor.gov：资产配置要随时间期限、风险承受力和目标变化；再平衡用于把组合拉回目标风险水平。
- CFP 类财务规划框架：目标、现金流、保险、负债、投资和复盘应作为整体，而不是分开决策。

### 2.2 投资方法论

投资方法论原件统一归口到 `references/methodologies/`，执行、记录和复盘仍放在 `{你的投资库}/`。

- 价值投资：生意质量、现金流、护城河、管理层、估值和安全边际。
- 资产配置：现金、债券、权益、黄金、海外资产、房产等承担不同组合功能。
- 估值纪律：当前价格隐含预期比目标价更重要。
- 技术分析：只服务执行节奏，不构成长期买入理由。
- 宏观周期：用于调整风险预算、仓位上限和分批节奏，不用于短期预测下注。
- 行为金融：识别追涨、亏损厌恶、确认偏误、锚定、过度自信和熟悉度偏误。

### 2.4 数据获取规则（2026-07-03 新增）

> 背景：比亚迪分析中误用动态 PE（Q1 年化 49x），实际静态 PE 为 24.7x。原因是手动计算而非从数据源获取，且未做多源交叉验证。以下规则为强制性约束。

#### 数据获取优先级

财务数据（PE、PB、EPS、ROE、营收、利润等）**禁止手工计算**。必须从实际数据源获取：

| 优先级 | 数据源 | 适用场景 | 调用方式 | 链接 |
|--------|--------|---------|---------|------|
| 1 | **AKShare** | A 股行情/财务/PE/PB | `python3 -c "import akshare..."` | [GitHub](https://github.com/akfamily/akshare) |
| 2 | **ttskill** | 天天基金持仓/盈亏/基金数据 | `ttskill invoke <SKILL_ID> --action ...`（本地 Skill，未安装自动跳过） | — |
| 3 | **futuapi** | 港股/美股实时行情/K 线 | 需 OpenD 运行 + 账户连接（本地 Skill，未安装自动跳过） | — |
| 4 | **yfinance** | 港美股历史/估值/财务 | `python3 -c "import yfinance..."` | [GitHub](https://github.com/ranaroussi/yfinance) |
| 5 | 东方财富 push2 API | A 股实时行情（AKShare 备用） | `curl` + `push2.eastmoney.com` | [push2.eastmoney.com](https://push2.eastmoney.com) |
| 6 | 腾讯 qt 行情 | A 股实时行情（AKShare 备用） | `curl` + `qt.gtimg.cn`（GBK 解码） | [qt.gtimg.cn](http://qt.gtimg.cn/q=) |

> **零配置原则**：运行时不要求用户安装任何东西。有 Python 库（akshare/yfinance）就用；没有 → 自动降级到 HTTP 接口（腾讯 qt / 东方财富，`curl` 即可）；本地 Skill（ttskill/futuapi）没有 → 自动跳过用公开源。

#### 交叉验证规则

1. **关键估值数据（PE/PB/市值）必须来自至少 2 个独立数据源**，偏差 >5% 需标注并解释原因。
2. **PE 优先使用静态 PE 或 TTM PE**，禁止单用动态 PE（Q1 年化）。如只有动态 PE 可用，必须标注"Q1 年化，可能有季节性偏差"。
3. **如果 AKShare 和富途都不可用**（代理故障/OpenD 未启动等），必须显式告知用户数据源限制，不隐藏问题。
4. **如果两个数据源互相矛盾**（偏差 >10%），必须暂停分析，标注"数据矛盾，待核实"，不允许强行收口。

#### 数据源故障处理

- 代理故障（本地代理不稳定）→ 用 `NO_PROXY="*" curl` 直连备用源
- AKShare 返回空 → 降级到腾讯/东财 API
- 全部不可用 → 明确告知用户，不编造数据
- **所有数值必须标注数据源和数据时间**，如"腾讯 qt 2026-07-03 收盘"
```

如果缺少关键事实，只能给初步判断，不能给强执行建议。

## 3. 总流程

任何家庭财务或投资决策，都按下面顺序执行：

```text
家庭目标和约束
→ 资产负债表
→ 现金流与安全垫
→ 保险保障
→ 房产与负债
→ 大类资产配置
→ 宏观与周期校正
→ 压力测试与黑天鹅
→ 投资组合和风险桶
→ 具体资产/基金/公司分析
→ 市场择时与执行窗口
→ 交易闸门
→ 操作记录
→ 定期复盘
```

这个顺序不能跳。单个标的再好，也不能越过现金流、安全垫和风险桶。

## 3.5 三档执行流程

为了避免系统过重导致用户绕开记录，所有请求先由 `家庭财务总控 Agent` 判定流程档位。

### 3.5.1 轻流程

适用：

- 已执行的小额记录。
- 计划内定投。
- 已在 IPS 或最新资产配置报告中批准的再平衡动作。
- 现金容器之间的小额转移。
- 不改变风险桶和大类资产目标的小调整。

步骤：

1. `账户与操作记录 Agent`：记录日期、金额、账户、标的、价格和资金来源。
2. `家庭资产负债表 Agent`：更新对应资产表或标记待更新。
3. `资产配置记忆`：若影响配置目标，追加执行状态；否则只保留操作记录。

轻流程不重新跑基本面、估值和完整反方审查，但必须检查是否属于计划内动作。

### 3.5.2 标准流程

适用：

- 常规买入、卖出、加仓、减仓。
- 单笔金额超过金融资产 1%，但未超过 2%。
- 风险桶内替换。
- 月度再平衡。
- 已研究过的公司、基金或资产类别。

步骤：

1. `家庭财务总控 Agent`：判定问题类型和流程档位。
2. `现金流与安全垫 Agent`：确认资金可用。
3. `大类资产配置 Agent`：确认资产类别和风险桶。
4. `风险与仓位 Agent`：确认仓位上限和最坏回撤。
5. `投资总控 Agent`：对已研究标的做 thesis 快速刷新，确认原投资逻辑、估值区间、反方证据和观察条件是否仍有效。
6. `市场择时与情绪 Agent`：给市场级执行节奏；如涉及具体标的交易，补充 `技术与市场行为 Agent` 的标的级价格结构检查。
7. `交易纪律与行为纠偏 Agent`：检查冷静期和行为风险。
8. `账户与操作记录 Agent`：记录并设置复盘。

标准流程不必每次重写完整公司报告，但必须引用已有报告或标记需更新。

### 3.5.3 重流程

适用：

- 首次买入新公司、新基金、新资产类别。
- 单笔金额超过金融资产 2%。
- 偏离 IPS 或家庭财务宪法。
- 同一风险桶已接近或超过上限。
- 用户明确表现出追涨、补仓、焦虑、急于翻本。
- 重大宏观、政策、财报或人生阶段变化。

步骤：

执行第 6 节完整 agent 链，并必须输出正式 memo 或专项报告。

重流程下，反方审查、压力测试和交易纪律都有否决权。

## 4. 决策分类

先判断用户当前请求属于哪一类：

1. **记录类**：更新资产、现金、保险、负债、买卖记录。
2. **诊断类**：分析家庭资产结构、现金流、保障、风险暴露。
3. **配置类**：调整大类资产目标比例和再平衡方案。
4. **研究类**：研究公司、基金、黄金、债券、房产等资产。
5. **交易类**：买入、卖出、加仓、减仓、清仓、定投。
6. **复盘类**：检查操作是否符合原计划。
7. **规则类**：更新家庭财务宪法、IPS、交易纪律。

交易类必须走完整闸门。记录类不能顺手给投资建议，除非用户明确要求。

## 5. 信息完整性检查

### 5.1 家庭层面

- 最新资产负债表是否存在。
- 金融资产、房产、车辆、负债、保险是否更新。
- 未来 6-12 个月收入和支出是否有重大变化。
- 是否有辞职、创业、购房、教育、医疗等大额资金需求。
- 现金和类现金是否达到安全垫。
- 是否存在不能投资的钱。

### 5.2 投资层面

- 当前持仓和成本。
- 标的价格、估值和数据来源。
- 所属资产类别和风险桶。
- 与已有资产是否重叠。
- 操作后仓位和最坏回撤。
- 失效条件和复盘日期。

### 5.3 信息不足时

必须明确写：

```text
当前只能给框架建议，不能给金额级执行建议。
缺少：X/Y/Z。
补齐后再输出正式方案。
```

## 6. Agent 协作顺序

> 本节描述的是领域判断顺序，不是 `.claude` 里的注册表或文件清单。
> 如果角色名称、文件路径或团队入口发生变化，以 `references/Agent索引.md` 为准。

重流程完整决策链如下。轻流程和标准流程按第 3.5 节裁剪，不需要每次调用全部 agent：

1. `家庭财务总控 Agent`：定义问题、调用子 agent、整合结论、检查是否跑偏。
2. `家庭资产负债表 Agent`：还原资产、负债、净资产、金融资产、房产和集中度。
3. `现金流与安全垫 Agent`：判断应急金、辞职窗口、创业备用金和未来现金流。
4. `风险保障与保险 Agent`：判断医疗、重疾、寿险、意外和保费压力。
5. `房产与负债 Agent`：判断房产集中度、房贷、提前还贷和流动性。
6. `大类资产配置 Agent`：判断现金、债券、权益、黄金、海外资产目标比例。
7. `宏观与周期 Agent`：校正利率、通胀、汇率、流动性、政策和经济周期。
8. `压力测试与黑天鹅 Agent`：测试收入中断、股市大跌、中概下跌、房价下跌、汇率波动等。
9. `基金与产品穿透 Agent`：穿透基金底层，识别重复暴露和伪分散。
10. `具体标的研究子流程`：进入公司/基金/资产研究、估值和标的级技术结构检查，不在本文件单独维护新的 Agent 实体。
11. `市场择时与情绪 Agent`：判断市场级估值分位、波动、情绪、分批节奏和暂停/重新开放条件，只服务执行节奏。
12. `交易纪律与行为纠偏 Agent`：检查坏习惯、冷静期、交易次数和情绪状态。
13. `反方审查 Agent`：提出最强反方，有否决权。
14. `账户与操作记录 Agent`：记录原始理由、执行结果和复盘评分。

## 7. 硬性否决规则

出现任意一条，系统不能给买入或加仓建议：

1. 现金安全垫不足。
2. 未来 6-12 个月收入不确定，且本次操作会降低现金安全垫。
3. 该资产所属风险桶已经超配。
4. 单一标的或单一基金超过上限。
5. 没有估值区间、仓位上限和失效条件。
6. 标的信息缺口过大，无法判断真实风险。
7. 操作理由主要来自短期新闻、涨跌或社交媒体观点。
8. 用户处在连续亏损、明显焦虑、追涨或急于翻本状态，且未过冷静期。
9. 反方审查给出“否决”。

否决后只能输出：

```text
不建议执行。
可以观察。
需要补信息。
需要等复盘窗口。
```

## 8. 市场择时、宏观和黑天鹅

### 8.1 市场择时

本系统不做顶部底部预测，只做三类择时：

- 估值择时：决定长期赔率和分批比例。
- 趋势择时：决定是否等确认、分几次买。
- 情绪择时：判断拥挤度和反身性风险。

技术面不能单独构成长期买入理由。

### 8.2 宏观周期

宏观只输出组合影响，不输出玄学预测：

- 利率影响债券、成长股、黄金、房贷和现金收益。
- 通胀影响现金购买力、黄金、商品和企业利润率。
- 汇率影响港美股、QDII、美元资产和人民币家庭资产集中度。
- 流动性影响成长股、港股科技和中概估值。
- 政策影响平台经济、地产、教育、医药、金融科技。

### 8.3 黑天鹅压力测试

至少测试：

- 12 个月无个人工资收入。
- 金融资产下跌 15%。
- 权益资产下跌 30%-50%。
- 中国互联网/中概下跌 40%。
- 房价下跌 20%-30%。
- 人民币明显贬值。
- 利率重新上行。
- 家庭成员重大疾病或意外。
- QDII 限购、交易受限或流动性恶化。
- 大额专项支出（创业备用金、装修等，可能已释放/暂不启动）若同期启动，现金垫扣除 12 个月固定支出后是否仍能保留至少 10% 缓冲。

压力测试结果直接影响仓位上限。

## 9. 输出标准

所有正式建议必须包含：

- 一句话结论。
- 本次问题归类。
- 使用的数据来源。
- 关键事实。
- 方法论依据。
- 风险桶判断。
- 是否通过交易闸门。
- 操作建议。
- 禁止动作。
- 分批节奏。
- 失效条件。
- 复盘日期。

不允许只写“适当优化”“长期看好”“建议关注”。
